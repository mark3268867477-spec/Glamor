# G'lam OS 应用安装与系统刷写操作规范

> **制定目的**：严格区分 **“安装 / 更新第三方或自研 APP”** 与 **“更新 / 强制刷新 G'lam OS 系统本体”** 的执行路径、目标存储介质与命令边界，确保未来在开发或 AI 协助执行指令时，**绝不误用 `idf.py flash` 覆盖 OS，也不会把系统更新误当成普通 APP 推包**。

---

## 一、 核心对比总览

| 对比维度 | 场景 A：安装 / 更新 APP | 场景 B：更新 / 强制刷新 G'lam OS 系统 |
| :--- | :--- | :--- |
| **用户常见指令关键词** | “装一个新 APP”、“安装软件”、“打包应用”、“推个 `.gla`/`.spk`/`.elf` 到板子上”、“在桌面上加个工具” | “更新系统”、“修改 OS 桌面/设置/内核”、“强制刷新系统”、“重刷固件”、“修改底层驱动并烧录” |
| **修改的源码目录** | `app_sdk_template/apps/<app_id>/` 或任意第三方工程目录 | `os_firmware/`（含 `main/`、`components/bsp/`、`components/swift_abi/`） |
| **编译产物** | `app.elf` + 校验封装包 `.gla`（兼容 `.spk`） | `glam_os.bin` + `bootloader.bin` + `partition-table.bin` |
| **写入的目标存储介质** | **外部 TF 卡**（`/sdcard/apps/<app_id>/`） | **ESP32-S3 片内 16MB Flash**（`ota_0` 分区 `0x20000`） |
| **传输/写入方式** | **应用层安全投包**（OS 正在运行时接收文件并写卡） | **ROM 下载模式硬件烧录**（`idf.py flash` / `esptool`） |
| **对原有 OS 的影响** | **零影响**（100% 不会顶掉、擦除或改写片内 Flash 中的 OS） | **覆盖刷新片内 Flash 中的 OS 本体**（不会格式化 TF 卡上的 `/sdcard/apps/` 与 `/sdcard/data/`） |
| **是否需要重启设备** | **不需要重启**（安装完桌面直接刷新图标，点击即可进 PSRAM 运行） | **需要重启**（烧录完成后芯片硬件复位进入新版 OS） |
| **禁止行为（红线）** | **严禁运行 `idf.py flash`、`esptool` 或 `os_firmware/flash.bat`** | **不可用 `.gla`/`.spk` 渠道二替代**（安装包严格校验 ELF 头并禁止擦写 Flash） |

---

## 二、 场景 A：安装 / 更新 APP（只进 TF 卡 `/sdcard/apps/`）

### 方式 1：使用可视化零环境控制器 **G'lamor**（推荐第三方开发者使用）
1. 解压 `release/Glamor_v1.0.0_Win64_Portable.zip` 后双击 `G'lamor.exe`（或双击仓库根目录 `启动_Glamor.bat`）。
2. 在「**1. 构建 & 打包 (.gla)**」页选择或新建工程，点击 **一键编译 · 体检 · 打包 (.gla)**（会自动检查 17 项 ABI 白名单符号并生成 `.gla`）。
3. 切换到「**2. 安装到设备**」页，任选 **Wi-Fi 无线推送 / USB 数据线串口 / TF 卡自动解包** 完成安装。

### 方式 2：使用命令行工具 `glamctl.bat` / `app_sdk_template` 脚本
1. **批量编译并打包官方示例应用成 `.gla`**：
   ```cmd
   cd /d "c:\Users\Mark\Desktop\esp32\glam_os_link\app_sdk_template"
   build_apps.bat
   ```
   产物输出在 `app_sdk_template\dist\<app_id>.gla`（如 `com.glam.music.gla`、`com.glam.racer.gla`、`com.glam.sysmon.gla`）。

2. **通过双渠道安全投递到 TF 卡（任选其一，严禁走 `esptool` 刷 Flash）**：
   * **渠道一（TF 卡离线导入）**：
     ```cmd
     :: 自动拷贝 .gla 到 /install/ 并直接解包 manifest.json + app.elf + icon.jpg 到 /apps/
     glamctl.bat install app_sdk_template\dist\com.glam.music.gla --sdcard E:\
     ```
     或者把 `.gla` 拷进 TF 卡 `/install/` 目录，插卡开机或在板子「应用中心」点扫描 / 「文件管理」直接点击安装。
   * **渠道二 A（Wi-Fi 无线推送 / 网页拖拽）**：
     ```cmd
     glamctl.bat install app_sdk_template\dist\com.glam.music.gla --wifi 192.168.1.50
     ```
     或在浏览器打开 `http://<板子IP>/`，选择 `.gla`（兼容 `.spk`）上传安装。
   * **渠道二 B（USB 串口安全传包）**：
     ```cmd
     glamctl.bat install app_sdk_template\dist\com.glam.music.gla --port COM7
     ```

### 物理隔离与防覆盖保障
* `glam_sdk` 与 OS 端 `os_spk_installer.c` 均强制校验 `"GLAM"`（或兼容 `"SWPK"`）魔数、CRC32 与 Xtensa ELF 头，**拒绝接收普通 `.bin` 固件**。
* `swift_os_abi.c` 的导出符号白名单**不包含任何 Flash 擦写与分区写入 API**，APP 代码在链接和加载阶段就无法触碰片内 Flash。

## 三、 场景 B：更新 / 强制刷新 G'lam OS 系统（刷新片内 Flash）

### 适用范围
* 修改了 G'lam OS 本体的任何代码：
  * 顶部状态栏、主桌面 Launcher、系统设置、文件管理、应用中心、时钟、计算器（`os_firmware/main/ui/os_ui.c`）；
  * ELF 加载器、ABI 导出接口（`os_firmware/components/swift_abi/`）；
  * BSP 硬件驱动、屏幕/触控/音频/TF 卡驱动（`os_firmware/components/bsp/`）；
  * 分区表（`os_firmware/partitions.csv`）或默认内嵌应用配置。
* 需要对开发板执行“强制刷新”或重新烧录底包时。

### 标准执行步骤
> **前提提醒**：ESP-IDF 构建工具链要求工作路径不含空格，脚本会自动维护无空格映射 `glam_os_link`。

1. **编译 G'lam OS 内核固件**（会先自动编译打包 `.gla` 示例应用，再编译整个 ESP-IDF 工程）：
   ```cmd
   cd /d "c:\Users\Mark\Desktop\esp32\glam_os_link\os_firmware"
   build.bat
   ```
2. **强制刷新烧录到 ESP32-S3 片内 Flash**（默认端口 `COM7`，可按实际端口修改）：
   ```cmd
   cd /d "c:\Users\Mark\Desktop\esp32\glam_os_link\os_firmware"
   flash.bat COM7
   ```

### 强制刷新系统后，TF 卡里的 APP 会丢吗？
* **不会丢失**！`flash.bat` 只擦写 ESP32-S3 芯片内部的 16MB SPI Flash，**外部 MicroSD (TF) 卡完全不受影响**。
* 刷完新 OS 重启开机后，桌面会自动重新扫描 TF 卡 `/sdcard/apps/`，原有 APP（包括旧版 `com.swift.*` 或新版 `com.glam.*`）和 `/sdcard/data/` 里的应用数据都会自动保留并正常显示。

## 四、 AI / 助手执行判定规则（快速自检表）

1. **指令涉及“装软件 / 更新某 App / 加个桌面应用 / 推 `.gla`、`.spk` 或 `.elf`”**
   * → 判定为 **场景 A（安装 APP）**。
   * → **只允许**修改应用目录，执行 `build_apps.bat` 或 `glamctl.py`（`--port` / `--wifi` / `--sdcard`）。
   * → **禁止**修改 `os_firmware/`，**严禁**执行 `idf.py flash` / `flash.bat`。

2. **指令涉及“改 OS 界面 / 改系统功能 / 加系统底层 API / 更新系统 / 强制刷新固件”**
   * → 判定为 **场景 B（刷新系统）**。
   * → 修改 `os_firmware/`，执行 `os_firmware\build.bat` 编译验证，并通过 `os_firmware\flash.bat <COMx>` 烧录片内 Flash。
